# dsh-router-b 整体优化方案（作战台）

目标：让 dsh-router-b 从“把需求拆给 worker”变成一个能撑起日常业务的**作战台**。日常业务指自建站运维、媒体运维和写代码。它的形态像一个 bot：

```
你（作战室 / 面板）
  └─ routing：只做识别分区与快速转发
       └─ 分区 manager：常驻身份，有记忆，默认最强模型，编排任务、了解本分区所有 session
            └─ worker session：可读、可续作、可停止、可重试
                 └─ 出口：git 分支与 PR、浏览器、网络出口、运维命令（高风险一律人工确认）
```

本文分五部分：目标场景、架构、各模块功能点（含现状差距）、人工确认设计、分期。

---

## 1. 目标场景

| 场景 | 典型需求 | 需要的能力 |
| --- | --- | --- |
| 写代码 | “给站点加一个订阅页，开 PR 给我看” | 分支隔离、提交、开或更新 PR、CI 结果回传、合并前人工确认 |
| 自建站运维 | “nginx 证书快到期了，续上并重载” | 运维命令分级（只读、可逆、危险），危险操作要确认，执行留痕 |
| 媒体运维 | “把这周的视频转码上传，封面截图给我看” | 长任务进度、文件产物、截图证据、失败重试 |
| 巡检 | “每天早上看一眼各站点是否正常” | 定时任务、浏览器截图、异常时通知 |
| 出口管理 | “这个模型端点走香港出口” | 与 dsh-egress 联动，manager 能看出口状态（只读） |

---

## 2. 架构

1. **routing（作战室 anchor）**：只识别分区，原话加上下文一次转发，一个分区一条 `route_task`。跨分区的先后顺序用 `depends_on` 表示。只有没开 manager 的分区才由 routing 自己拆。
2. **分区 manager**：每个需求起一个 manager 子会话，但身份是常驻的。分区记忆会自动注入它的提示词，记忆包括：
   - 常驻笔记：长期约定、人工记的规则；
   - 最近完成的工作：谁做的、改了哪些文件、留下什么；
   - 本分区可读、可续作的 worker session 列表。
   manager 用 `session_list`、`session_read` 看以前的工作，用 `task_resume` 在原 session 里续作，用 `partition_memory` 记或删笔记。
3. **worker session**：执行层。结束后写入分区工作日志。人工可以停止、重试、挂起或续作。
4. **出口层**（第二、三期）：git/PR、浏览器、网络出口、运维命令，统一走“出口策略”：每个出口在每个分区可设为禁用、只读、需确认或允许，每次调用都记审计日志。

数据都在 `<boardDir>` 下：`board.json`（任务）、`tiers.json`（模型档位与 manager 模型）、`memory/<分区>.json`（分区记忆）。之后会加 `egress-policy.json` 和 `audit/`。

## 3. 各模块功能点

图例：✅ 已有　🟢 第一期（本次 PR）　🟡 第二期　🔵 第三期　❓ 待你确认

### 3.1 发需求（routing 入口）
- ✅ 作战室一句话发需求，自动识别分区
- 🟢 路由改成快速转发：不替 manager 拆，原话加上下文一次发出
- ✅ 跨分区用 `depends_on` 排先后，同分区用 `stage` 分阶段
- 🟡 面板 Composer 可以手动指定分区（现在只能自动识别）
- 🟡 需求模板：常用运维操作做成一键模板（续证书、重载 nginx、转码上传）

### 3.2 manager 编排
- 🟢 manager 默认使用最强模型，可在「模型档位」里改：自动选最强、跟随默认、或指定某个模型（用它的最高推理档）
- 🟢 分区记忆注入、`session_list` / `session_read` / `partition_memory` 三个工具
- ✅ 按 stage / depends_on 顺序派发；manager 有子任务没结束时会被叫回来等
- 🟡 看计划：manager 先输出计划（子任务、顺序、分区），面板显示成一棵树
- ❓ 改计划或确认后再派：计划需要你点「开始」才派发（会慢一点，但可控）

### 3.3 session / worker 控制面
- 🟢 停止单个任务或 worker（二次确认，立刻生效，界面先变再回滚）
- 🟢 停止整个需求：manager 和它下面所有没结束的任务一起停
- 🟢 工作区页「停止全部」：停该分区所有需求
- 🟢 人工停止后通知还在跑的 manager：不要重派、不要再等
- 🟢 已停止的任务可以重试；分区记忆记一笔「人工停止」
- 🟢 操作按钮常显（以前要鼠标悬停才出现）
- ✅ 挂起（带前置）、续作、失败重试、中断后自动恢复
- ❓ 面板里直接看 worker 实时输出（现在要点开 session）
- ❓ 改派到别的分区，或换模型重跑
- ❓ 多选批量操作

### 3.4 分区与工作区
- ✅ 工作区页：分区列表、文件树、包含/排除规则、配置问题、进行中任务
- 🟢 「分区记忆」面板：manager 实际用的模型、常驻笔记（可加可删）、最近工作、worker session（点开即看）
- 🟡 在面板里新建、编辑分区（现在要改配置并重启）
- 🟡 每个分区的并发数、默认模型档位在面板里调

### 3.5 进度、通知、历史
- ✅ 进度提醒、按需求汇总的进度条
- 🟢 任务板搜索：按标题、编号、工作区过滤
- 🟡 历史搜索：在分区工作日志里搜（文件名、关键词）
- 🟡 完成或失败时推送通知（接现有通知渠道）
- 🔵 定时巡检任务（每天检查站点、证书到期、磁盘）

### 3.6 代码出口：分支与 PR
现状：路由不碰 git，只在 brief 里写分支规则（`partition.git.branch`）。
- 🟡 每个需求自动一个分支，或一个 git worktree，互不干扰
- 🟡 worker 结束后自动提交；manager 汇总后开 PR 或更新 PR，PR 链接回写任务行
- 🟡 CI 结果回传到任务行，失败时可一键让原 worker 修
- 🟡 合并必须人工在面板点「合并」，worker 和 manager 都没有合并权限
- ❓ 用 GitHub 还是自建 Gitea / GitLab

### 3.7 浏览器出口
现状：只有一次性截图命令 `/srv/workspace/bin/screenshot`，结果当证据存进 `.dsh-artifacts`。
- 🟡 截图和页面文字抓取做成正式工具（带分区白名单域名）
- 🔵 可交互浏览器（登录后台、点按、填表），每一步写审计日志；提交表单、付款、删除之类的操作要人工确认
- ❓ 浏览器跑在服务器（无头、省内存）还是用你本机的 Chrome

### 3.8 网络出口（dsh-egress 联动）
- ✅ dsh-egress 管模型请求走哪个代理，agent 只有只读的 `egress_status`
- 🟡 manager 和 worker 能查看出口状态（只读），出口失败时任务行显示原因
- 🟡 worker 的外部请求（下载、上传媒体）也按分区选出口

### 3.9 运维命令
- 🟡 命令分级：只读（查看日志、状态）直接跑；可逆（重载配置）记日志；危险（重启服务、删文件、改 DNS）先停下等你确认
- 🟡 每个分区的危险命令清单写在配置里
- ✅ 硬规则：worker 不准直接写 host 插件的 lib/，也不准重启 DSH

### 3.10 配置与恢复
- ✅ 模型档位（简单、中等、困难），在线读取可用模型
- 🟢 Manager 模型一行：显示实际用哪个
- ✅ 重启后中断的任务自动续作，超过次数停给人工
- 🟡 面板显示 host 版本，提示需要 `safe-build-host.sh` 加 `safe-restart.sh`

## 4. 人工确认设计（高风险出口）

所有“出去”或“不可撤回”的动作，统一走一个确认队列：
1. worker 或 manager 调用出口工具。策略为“需确认”时，工具不执行，只生成一张确认卡，任务行变成「等你确认」。
2. 确认卡写清楚：要做什么、对哪个目标（分支、PR、域名、命令）、影响范围、能不能撤回。
3. 你在面板点「同意」或「拒绝」。同意只对这一次生效，没有“以后都同意”。
4. 结果和审计记录（时间、谁同意、执行输出摘要）写进 `audit/`，并回到任务行。

默认需要确认的动作：合并 PR、推送到默认分支、浏览器里提交表单或登录、对外发消息、危险运维命令、删除媒体文件、改出口绑定。

## 5. 分期

| 期 | 内容 | 状态 |
| --- | --- | --- |
| 第一期 | 架构骨架（routing 快速转发 → manager → session → worker）；分区记忆和 session 感知；manager 默认最强模型；停止与控制面（单个、整个需求、分区全部、通知 manager、乐观更新、可重试）；工作区记忆面板；任务板搜索 | 本次 PR |
| 第二期 | git 分支与 PR 出口（GitHub，可切 Gitea）；确认队列和审计；运维命令分级；无头截图和取正文；**提前做了**实时输出、改派和换模型、批量操作；面板日夜主题与简洁风格 | 第二期 PR（叠在第一期之上） |
| 第三期 | 每个需求独立 worktree；可交互浏览器；定时巡检；面板新建和编辑分区；manager 计划可视化；手动指定分区；历史搜索 | 待排期 |

第二期怎么做的、依赖哪些 DSH 接口、升级怎么核对，见 [ARCHITECTURE.md](./ARCHITECTURE.md)。

## 6. 待确认（第二期按默认做了，你看一眼要不要改）

1. **出口默认策略**：git / 命令 / 浏览器 默认都是“放行”，只有合并 PR 和危险命令要确认。想更保守就把某个分区设成 `confirm`。
2. **危险命令清单**：`rm`、`dd`、`mkfs`、`reboot`、`kill`、`systemctl stop/restart/disable`、`docker rm/stop/compose down`、`git push --force`、`reset --hard`、防火墙、改用户、`chmod 777 /`、`DROP TABLE` 等。`systemctl restart` 算危险（会断服务）；`nginx -s reload`、`docker run` 不算。要增减用分区的 `outlets.danger`。
3. **合并方式**：默认 `squash`，合并前再核对一次 PR 头提交，变了就作废要重新申请。
4. **确认卡有效期**：24 小时，过期自动作废。
5. **改派次数**：一个任务只能改派一次（对新任务可以继续改派），避免一条链越拉越长。
6. **浏览器白名单**：默认不限域名（只限 http/https）。媒体站建议给每个分区配 `browserAllow`。
7. **主题“跟随系统”**：先看 DSH 外壳的暗色标记，再看操作系统设置。
8. **令牌变量名**：默认 `GITHUB_TOKEN` / `GITEA_TOKEN`，可在分区 `git.scm.tokenEnv` 改。
9. **`ops_run` 不是硬隔离**：worker 自己仍有 shell。要强制只走出口，需要在 DSH 配置里收掉 worker 的 shell 工具。
